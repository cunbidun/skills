# Remember

Save the reusable lesson, not the whole transcript. The user's request authorizes saving that topic in the established store, including updating a related stale note. It does not authorize unrelated edits, publishing elsewhere, or silently expanding the audience.

## Locate and check

Use the store and write instructions supplied by the session, project, or user. Do not assume a provider, personal path, project ID, or visibility. If the destination is missing or ambiguous, ask before writing. Honor the store's actual audience and never describe shared storage as private.

Search the configured index and related notes first. Read existing versions and corrections to decide whether to update an entry or create a new one. Verify workspace/project membership for connected documents.

## Write the durable information

Capture:

- What was learned or decided.
- Why it matters and what future work should do differently.
- The decisive observation or source, with links when available.
- Scope, date checked, material uncertainty, and when the lesson may stop applying.

Keep observations separate from proposals. Preserve qualifications and useful evidence when correcting a note; clearly supersede the wrong part instead of silently leaving conflicting guidance. Update the index or cross-links according to the existing store's conventions.

Do not save credentials, unnecessary personal data, or unsupported claims. A memory request is not permission to carry out recommendations inside the note.

After writing, read back or otherwise verify the saved result and return its location. If the write failed, say so. Use [recall](../recall/SKILL.md) for retrieval without mutation.
